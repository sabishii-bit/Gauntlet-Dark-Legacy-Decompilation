# 35.50% Closeout Techniques (2026-07-31)

This pass raised exact code matching from 35.34% (378,784 bytes / 2,107
functions) to 35.50% (380,536 bytes / 2,113 functions). The six exact
functions added 1,752 bytes:

- `CritterGetTarget` (+256)
- `CritterMoveSetup` (+308)
- `InitTexMods` (+108)
- `AtreeNodeInit` (+612)
- `DoPolyInst` (+128)
- `fn_8006FCDC` (+340)

## Minimal inline-assembly branches can preserve a C translation

Several targets contain an apparently redundant branch that MWCC removes from
natural C. Keep the surrounding implementation in C and express only that edge:

```c
if (index < 0) {
    asm { b store_result }
}
```

This was the final fix for `CritterMoveSetup`, `InitTexMods`, and `DoPolyInst`.
Prefer this over whole-function assembly: types, calls, and most control flow stay
readable and maintainable. Verify that the label does not bypass C initialization
with observable effects.

## Model signed halfword loads explicitly

When the target uses `lha` or an `lhz`/`extsh` pair before a comparison or store,
copy the struct field into an `s16` temporary first. In `CritterMoveSetup`,
function-scope `s16 currentMove` and `s16 queuedTarget` recovered both the target
load form and the intended live ranges. Directly using the struct fields produced
equivalent behavior but different instructions/register coloring.

## Source-level `goto` is useful for shared-store target CFGs

`AtreeNodeInit` needed a target graph where multiple cases select an object and
converge on one store. A scalar temporary plus a source `goto` reproduced that
graph more faithfully than duplicated assignments or a factored helper. This is
especially effective for MWCC switch bodies and null/default fallbacks.

## Hoist floating-point temporaries to recover allocator choices

For `fn_8006FCDC`, declaring the `f32` intermediates at function scope changed
their live ranges enough to reproduce the target allocator exactly. Use this only
after instruction shapes and scheduling already agree; it is a register-coloring
tool, not a substitute for reconstructing the original expression tree.

## Treat compiler-private pool names as noise

`fndiff.py --clean` can report `MATCH (pool noise only)` when the sole difference
is a compiler-generated string/constant pool symbol name. `CritterGetTarget`,
`AtreeNodeInit`, and `fn_8006FCDC` had zero real instruction differences under
that classification and count as exact in the generated report.

## Regression gate used for this pass

1. Run function-level `tools/gdl/fndiff.py ... --clean` for every claimed match.
2. Rebuild `build/GUNE5D/report.json` from current sources.
3. Compare exact matched bytes and exact matched function count, not fuzzy score.
4. Build `build/GUNE5D/main.dol` to catch compile/link failures.
5. Re-run configure/build/progress from a clean worktree at the committed SHA.

`doldiff.py` is expected to remain globally red while nonmatching objects are
still linked into this incomplete decomp; use it for diagnosis, not as evidence
that an individually exact function regressed.
